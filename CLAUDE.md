# Project notes for the agent

- This is a Vite + React static site deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`. It serves at `https://<domain>/<repo-name>/`.
- `package.json` "name" must equal the GitHub repo name. `vite.config.js` derives the `base` path from it.
- `site.config.js` holds the domain, title, description, and OG copy. `scripts/prerender.mjs` reads it at build time and writes the meta tags, JSON-LD, sitemap, and the index-site embed script tags into `dist/index.html`.
- `pnpm run build` is `vite build` plus the prerender. The deployed HTML contains the rendered page, so `src/main.jsx` uses `hydrateRoot`, and nothing may read `window` during render. Apply URL state in a `useEffect` after mount.
- Shareable state goes in the URL with `replaceState` (`src/urlState.js`). The analytics embed counts each `replaceState` as a pageview.
- Analytics: `window.dhAnalytics?.track(name, props)`, optional-chained because the embed is third-party and blockable.
- Hover interactions use `onPointer*` events, not `onMouse*`, so they work on touch.
- Favicon and OG images are generated by `pnpm run gen:favicon` and `pnpm run gen:og` on a developer machine and committed. CI does not regenerate them. Re-run after a redesign.
- Dev server: `pnpm run dev`. If port 5173 is busy, `pnpm run dev -- --port 5174`.
- The `dataviz-pages-site` skill covers everything else: build-time data, researched datasets, mobile, dates, SEO, registering the project card on the index site.
- Data is committed. The games since 2001 are cfbfastR's schedules through 2025 and, from the 2026 season on (`STREAK_KING_FROM` in `build-candidates.mjs`), College Football Streak King's published payload (`https://drewhoover.com/cfb-streak-king/share/payload.json`, cached as `data/raw/streak-king/payload.json`): the same schedule plus CFBD's finals for games cfbfastR hasn't marked yet, and each game's overtimes, so those games need no ESPN fetch. The two sources agree on every 2025 qualifying game (158 of 158, scores, host ranks and overtimes). The coaches and the polls are still this repo's own. The committed data is the data (2026-11-16). In season the deploy workflow's scheduled runs (every day at 19:00 and 23:00 UTC, August through January, `schedule` in `.github/workflows/deploy.yml`) and a `workflow_dispatch` run `node scripts/refresh.mjs` with `data/raw/` restored from the Actions cache, build, commit `data/` and `src/data/` to main as "the refresh" and deploy that commit, the share worker included; a push builds what main holds and fetches nothing. A refresh that finds no game the commit doesn't have puts the committed files back (only the date stamps had changed), and a scheduled run then commits and deploys nothing. A refresh that fails commits and deploys nothing, the site keeps what it had, and the run opens an issue titled "The data refresh failed". So pull with a rebase before you push, and don't commit data older than main's: `scripts/check-not-older-than-live.mjs` fails a deploy whose data is dated before the live site's `data.json` or has fewer games (put `[older data]` in the commit message to ship it on purpose). Until this date a refresh deployed without committing and built the committed data when it failed: on 2026-11-16 Streak King's payload answered 526, the run went green, and the board went back nine days. `scripts/refresh.mjs` is the runbook below as one command. The raw sources live under `data/raw/` (gitignored) and `scripts/fetch-data.mjs` is cached per file, so by hand the refresh is: delete `data/raw/streak-king/payload.json` and `data/raw/ap-polls/season-2026.html` (the running season's two files; new poll pages download as missing), `node scripts/fetch-data.mjs --only=games` and `--only=polls`, then `node scripts/build-candidates.mjs`, `node scripts/build-records.mjs`, `node scripts/fetch-ot.mjs` (ESPN overtime for cfbfastR game ids; a Streak King game carries its own) and build-records again so `ot.json` reaches `data/records.json` and `src/data/site-data.json`. Check with `node scripts/candidate-stats.mjs` (no seasons flagged) and `node scripts/coverage-report.mjs`; its Kiffin check fails on purpose since he went 1-9. 2026 unmatched games are G5/FCS road teams with no tenure row. A game played after the bulk fetch can be hand-added in `data/game-corrections.json` (`action: "add"`, scored from ESPN) and yields automatically once Streak King's payload carries it.
- The board runs from 1936 (`specs/back-to-1936.spec.md`). Howell's pages are the game source before 2001 and the AP polls go back to 1936, so `data/raw/` has to reach 1936 too: `build-candidates.mjs` exits with a message when it doesn't (`fetch-data.mjs --only=jhowell` and `--only=polls` fill it). Pre-1990 coaches come from `data/coach-stints.json`, which `CSK_DIR=../cfb-streak-king node scripts/build-coach-stints.mjs` generates from cfb-streak-king's committed payload; re-run it only when that repo's coach data changes, and never hand-edit it (a spelling goes in `data/coach-aliases.json`, scope in `rules.json` `pre_1990_power`). `build-records.mjs` attributes pre-1990 games from the stints only and writes the payload in two files: `site-data.json` (1990+, the prerender) and `site-data-1936.json` (loaded after mount). Every pre-1990 game carries two receipts (Howell's row, the host's poll row); after a rebuild that touches them, `node scripts/save-pages.mjs data/games-candidates.json data/coach-stints.json` then `node scripts/check-receipts.mjs --offline data/games-candidates.json data/coach-stints.json` must pass. The saved pages under `data/research/pages/` are committed. Open threads are in `data/research/leads.json`.
- The og:image is the current-coaches poster (`ogImage` in `site.config.js`), so regenerate it with the data: `pnpm exec vite --port 5173` for the logos, `node scripts/gen-poster.mjs > /tmp/poster.html`, render with Chrome (`--headless=new --hide-scrollbars --force-device-scale-factor=2 --window-size=1560,1400 --virtual-time-budget=8000 --screenshot=...`), trim the trailing background rows with sharp keeping ~72px of bottom padding → `public/current-coaches-road-vs-top10.png` (2x), downscale to width 1560 → `public/og-poster.png`, and set `ogImageHeight` in `site.config.js` to the result (1407 as of 2026-11-23). The dev server's logos can be file paths instead: pipe the HTML through `sed "s#http://localhost:5173/hostile-territory/#file://$PWD/public/#g"` and add `--allow-file-access-from-files`. Render taller than the page (`--window-size=1560,1700`), since a window shorter than the board cuts its last row off. `pnpm run gen:og` redraws the Kiffin card, which only changes when he plays a road game vs the top 10.
- The intro line (`src/App.jsx`) and the description (`site.config.js`) stay pinned to ESPN's 1-8 factoid, with Kiffin's live number beside it. On the page and the og card (`og.png`, `card.png`) the line is every record he has held since: ESPN's 1-8, then his record after each top-10 road game since, each struck through on its own and the last one live ("~~1-8~~ ~~1-9~~ 1-10", Drew's call 2026-11-22). `kiffinSteps` in `src/kiffin.js` lists them for both. The meta description keeps the factoid in parentheses. Everything computes from `src/data/site-data.json`, so a data refresh moves the page and the description without an edit; the og card and the poster need `pnpm run gen:og` and the poster's render, since CI doesn't redraw images.
- The dateline sits above the title as on Streak King: provenance on the left, the icon bar on the right (search, Ko-fi, share). Its "updated" stamp is `generated` in `src/data/site-data.json`, the data build date (hidden on phones, with the years). The search icon (`src/FindCoach.jsx`) finds a coach by name or school and opens his row (`coach_open` with `from: 'find'`); it replaced the board's filter box, so `?q=` no longer filters. The share icon uses `src/useShare.js` (native share sheet, else copy "text url" and flash "copied") and tracks `share`. Ko-fi is `KOFI_URL` in `src/Notes.jsx`, in three places: the coffee icon in the dateline (`from: 'icons'`), the Method paragraph (`from: 'notes'`) and the footer (`from: 'footer'`).
- What to read next is Putting Up Numbers' claims about the open coach and his school (puttingupnumbers' `specs/read-next-across-sites.spec.md`). The back-bar embed carries `data-section="sports" data-read-next="cfb"`: it fetches and shuffles PUN's links and draws them in the top bar, and the block under the board (`src/ReadNext.jsx`) shows the first five of its order as sentences. `src/readNext.js` sets the subject on `<html>` (`data-dh-subject="coach:<PUN slug>"` and `data-dh-team`); `src/punSlugs.json` holds the coaches whose PUN address isn't their slug here. The prerender bakes PUN's college football list into the page (`scripts/lib/readNext.mjs`; a failed fetch bakes nothing; `READ_NEXT_ORIGIN` points it at a local server). Events: `readnext shown` and `readnext` with `where: 'block'` (the embed counts the bar's). The other sports sites' list is in `scripts/lib/llms.mjs`, for `dist/llms.txt` alone.
- Venues (section 2 of `specs/three-sites-search.spec.md` in puttingupnumbers, as Drew changed it 2026-11-02): the board's first toggle picks road (the default), home, neutral site or all, `?venue=home|neutral|all`. The road games are the board's own, each with a receipt. Home and neutral-site games are College Football Streak King's payload, tallied by `scripts/build-venues.mjs` into `src/data/venue-games.json` (every such game against a ranked team, per coach, in site-data's row shape with the coach's points first and the venue last; loaded the first time a reader picks a venue) and `src/data/venues.json` (the tallies the card draws). Both are committed and `refresh.mjs` rebuilds them. The two sources disagree on about 120 coaches' road counts by a game or two (Howell's '@' marker against Streak King's neutral flag, mostly), and the board uses its own. There are no coach pages (they shipped for one night and Drew turned them down): `/coach/<slug>/` is the board with that coach open, the way Streak King's definition pages are its board on a definition. The board reads the coach from the path (`readCoachPath` in `src/urlState.js`), opens him once the 1936 file and the venue's games are in, keeps his row whatever the filters say, scrolls to it, and writes the path as rows open and close (`writeCoachPath`). A `?coach=<name>` address still opens him, and the worker 301s it to the path. The sitemap lists every coach's address.
- The share worker (`workers/share/`, `hostile-territory-share`, on `drewhoover.com/hostile-territory/*`) serves the board's HTML at `/coach/<slug>/` (Pages has the one page) with his `<head>`: his title, his record at every venue as the description (`coachLead` in `src/coach.js`), his address as the canonical, and his card at `/share/coach/<slug>.png?cut=&venue=`, which renders the view the shared URL names, not the site's premise: the view's record in Graduate with its percentage under it, one sentence ("against the top 25, at every venue, since 2021"), and every game of the view as the board's chips — the opponent's mark on a cream or dark square, his AP rank under it (`#11`), `@` marking road games when the view mixes venues; a career too long for readable rank labels (Paterno's 164) drops them and shrinks the chips. The chips' marks are `public/logos-ink/` (win) and `public/logos-dim/` (loss, tie), baked by `scripts/gen-chip-logos.mjs` because satori can't run CSS filters — rerun it after `gen-logos` adds a team; the worker fetches them from the origin and inlines them. The head rewrite carries the view too: title and description from `?cut=` and `?venue=` (`viewLead` + `coachLead`), og:image pointing at the card with the same params. It bundles `src/data/*.json` and `src/coach.js`; bump `CARD_VERSION` in `workers/share/index.ts` with any change to what a card draws. Everything else passes through to Pages; a link preview of the board is counted in Mixpanel as `share unfurl`. The deploy workflow's `worker` job deploys it after every deploy, a refresh's included, from the commit the site was built from (the `CLOUDFLARE_API_TOKEN` secret); `pnpm run worker:deploy` by hand. Locally: `pnpm run build && pnpm run preview`, then `pnpm run worker:dev` (http://localhost:8789/hostile-territory/coach/lane-kiffin/; the static preview alone 404s a coach's address).
