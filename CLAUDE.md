# Project notes for the agent

- This is a Vite + React static site deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`. It serves at `https://<domain>/<repo-name>/`.
- `package.json` "name" must equal the GitHub repo name. `vite.config.js` derives the `base` path from it.
- `site.config.js` holds the domain, title, description, and OG copy. `scripts/prerender.mjs` reads it at build time and writes the meta tags, JSON-LD, sitemap, and the index-site embed script tags into `dist/index.html`.
- `npm run build` is `vite build` plus the prerender. The deployed HTML contains the rendered page, so `src/main.jsx` uses `hydrateRoot`, and nothing may read `window` during render. Apply URL state in a `useEffect` after mount.
- Shareable state goes in the URL with `replaceState` (`src/urlState.js`). The analytics embed counts each `replaceState` as a pageview.
- Analytics: `window.dhAnalytics?.track(name, props)`, optional-chained because the embed is third-party and blockable.
- Hover interactions use `onPointer*` events, not `onMouse*`, so they work on touch.
- Favicon and OG images are generated by `npm run gen:favicon` and `npm run gen:og` on a developer machine and committed. CI does not regenerate them. Re-run after a redesign.
- Dev server: `npm run dev`. If port 5173 is busy, `npm run dev -- --port 5174`.
- The `dataviz-pages-site` skill covers everything else: build-time data, researched datasets, mobile, dates, SEO, registering the project card on the index site.
- Data is committed. The games since 2001 are cfbfastR's schedules through 2025 and, from the 2026 season on (`STREAK_KING_FROM` in `build-candidates.mjs`), College Football Streak King's published payload (`https://drewhoover.com/cfb-streak-king/share/payload.json`, cached as `data/raw/streak-king/payload.json`): the same schedule plus CFBD's finals for games cfbfastR hasn't marked yet, and each game's overtimes, so those games need no ESPN fetch. The two sources agree on every 2025 qualifying game (158 of 158, scores, host ranks and overtimes). The coaches and the polls are still this repo's own. In season the deploy workflow refreshes it Sunday at 22:00 UTC and Monday at 13:00, after Streak King's Sunday refresh (`schedule` in `.github/workflows/deploy.yml`, August through January) by running `node scripts/refresh.mjs` before the build, with `data/raw/` restored from the Actions cache; a failed refresh builds the committed payload. A commit of the refreshed data still has to be made by hand (CI deploys it without committing), and `workflow_dispatch` runs the same refresh any day. `scripts/refresh.mjs` is the runbook below as one command. The raw sources live under `data/raw/` (gitignored) and `scripts/fetch-data.mjs` is cached per file, so by hand the refresh is: delete `data/raw/streak-king/payload.json` and `data/raw/ap-polls/season-2026.html` (the running season's two files; new poll pages download as missing), `node scripts/fetch-data.mjs --only=games` and `--only=polls`, then `node scripts/build-candidates.mjs`, `node scripts/build-records.mjs`, `node scripts/fetch-ot.mjs` (ESPN overtime for cfbfastR game ids; a Streak King game carries its own) and build-records again so `ot.json` reaches `data/records.json` and `src/data/site-data.json`. Check with `node scripts/candidate-stats.mjs` (no seasons flagged) and `node scripts/coverage-report.mjs`; its Kiffin check fails on purpose since he went 1-9. 2026 unmatched games are G5/FCS road teams with no tenure row. A game played after the bulk fetch can be hand-added in `data/game-corrections.json` (`action: "add"`, scored from ESPN) and yields automatically once Streak King's payload carries it.
- The board runs from 1936 (`specs/back-to-1936.spec.md`). Howell's pages are the game source before 2001 and the AP polls go back to 1936, so `data/raw/` has to reach 1936 too: `build-candidates.mjs` exits with a message when it doesn't (`fetch-data.mjs --only=jhowell` and `--only=polls` fill it). Pre-1990 coaches come from `data/coach-stints.json`, which `CSK_DIR=../cfb-streak-king node scripts/build-coach-stints.mjs` generates from cfb-streak-king's committed payload; re-run it only when that repo's coach data changes, and never hand-edit it (a spelling goes in `data/coach-aliases.json`, scope in `rules.json` `pre_1990_power`). `build-records.mjs` attributes pre-1990 games from the stints only and writes the payload in two files: `site-data.json` (1990+, the prerender) and `site-data-1936.json` (loaded after mount). Every pre-1990 game carries two receipts (Howell's row, the host's poll row); after a rebuild that touches them, `node scripts/save-pages.mjs data/games-candidates.json data/coach-stints.json` then `node scripts/check-receipts.mjs --offline data/games-candidates.json data/coach-stints.json` must pass. The saved pages under `data/research/pages/` are committed. Open threads are in `data/research/leads.json`.
- The og:image is the current-coaches poster (`ogImage` in `site.config.js`), so regenerate it with the data: `npx vite --port 5173` for the logos, `node scripts/gen-poster.mjs > /tmp/poster.html`, render with Chrome (`--headless=new --hide-scrollbars --force-device-scale-factor=2 --window-size=1560,1400 --virtual-time-budget=8000 --screenshot=...`), trim the trailing background rows with sharp keeping ~72px of bottom padding → `public/current-coaches-road-vs-top10.png` (2x), downscale to width 1560 → `public/og-poster.png`, and set `ogImageHeight` in `site.config.js` to the result (1375 as of 2026-10-18). `npm run gen:og` redraws the Kiffin card, which only changes when he plays a road game vs the top 10.
- The intro line (`src/App.jsx`) and the description (`site.config.js`) stay pinned to ESPN's 1-8 factoid, with Kiffin's live number beside it (the factoid struck through on the page, in parentheses in the meta). Both compute the live number from `src/data/site-data.json` through `src/kiffin.js`, so a data refresh moves it without an edit.
- The dateline's "updated" stamp is `generated` in `src/data/site-data.json`, the data build date (hidden on phones). The share icon beside it uses `src/useShare.js` (native share sheet, else copy "text url" and flash "copied") and tracks `share`. Ko-fi is `KOFI_URL` in `src/Notes.jsx`, in three places: the coffee icon beside share in the dateline (`from: 'icons'`), the Method paragraph (`from: 'notes'`) and the footer (`from: 'footer'`).
- `src/siblings.js` is the other sports sites, in the order and words every sports site shares; it feeds What to read next and `dist/llms.txt` (`scripts/lib/llms.mjs`, written by the prerender). The back-bar embed carries `data-section="sports"`.
- Venues (section 2 of `specs/three-sites-search.spec.md` in puttingupnumbers, as Drew changed it 2026-11-02): the board's first toggle picks road (the default), home, neutral site or all, `?venue=home|neutral|all`. The road games are the board's own, each with a receipt. Home and neutral-site games are College Football Streak King's payload, tallied by `scripts/build-venues.mjs` into `src/data/venue-games.json` (every such game against a ranked team, per coach, in site-data's row shape with the coach's points first and the venue last; loaded the first time a reader picks a venue) and `src/data/venues.json` (the tallies the card draws). Both are committed and `refresh.mjs` rebuilds them. The two sources disagree on about 120 coaches' road counts by a game or two (Howell's '@' marker against Streak King's neutral flag, mostly), and the board uses its own. There are no coach pages (they shipped for one night and Drew turned them down): `/coach/<slug>/` is the board with that coach open, the way Streak King's definition pages are its board on a definition. The board reads the coach from the path (`readCoachPath` in `src/urlState.js`), opens him once the 1936 file and the venue's games are in, keeps his row whatever the filters say, scrolls to it, and writes the path as rows open and close (`writeCoachPath`). A `?coach=<name>` address still opens him, and the worker 301s it to the path. The sitemap lists every coach's address.
- The share worker (`workers/share/`, `hostile-territory-share`, on `drewhoover.com/hostile-territory/*`) serves the board's HTML at `/coach/<slug>/` (Pages has the one page) with his `<head>`: his title, his record at every venue as the description (`coachLead` in `src/coach.js`), his address as the canonical, and his card at `/share/coach/<slug>.png` (his road record against the top 10 in Graduate, his record at every venue and on the road against the top 25 beside it, his road games against the top 10 as the board's cream and dark squares). It bundles `src/data/*.json` and `src/coach.js`; bump `CARD_VERSION` in `workers/share/index.ts` with any change to what a card draws. Everything else passes through to Pages; a link preview of the board is counted in Mixpanel as `share unfurl`. The deploy workflow's `worker` job deploys it after every push (the `CLOUDFLARE_API_TOKEN` secret); `npm run worker:deploy` by hand. Locally: `npm run build && npm run preview`, then `npm run worker:dev` (http://localhost:8789/hostile-territory/coach/lane-kiffin/; the static preview alone 404s a coach's address).
